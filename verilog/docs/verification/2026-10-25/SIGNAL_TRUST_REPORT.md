## 重大更正与突破（2026-10-25 深夜追加）：PEAK_VMIN 误杀垂位重试泵 → 纯自摆恢复

**回归发现**：用户指认三次"成功"均为手动助力后，重新解剖 10-24 纯自摆成功记录
（`../2026-10-24/swingup_factory_run1.bin` 11.9s/5 泵、`swingup_run3.bin` 8.4s/3 泵）：

| 成功案例 | 泵事件 | 泵前 adot（cdeg/s） |
|---|---|---|
| factory_run1 | #1/#2/#3/#5 垂位附近 | **+84 ~ +1462**（近静止） |
| factory_run1 | #4 高位转折 | -24193 |
| run3 | #1/#2/#3 全部垂位附近 | **+68 ~ +563** |

**成功机制还原**——不是"渐进积累"，是**垂位重试**：杆被泵甩到 ~150°@300°/s 冲顶 → 过顶太快未捕获 → 能量衰减垂死 → **垂位静止时 adot 微过零再触发泵 → 重新甩起 → 再冲顶**，直到某次甩起恰好低速过顶被捕获（run1 试 5 次、run3 试 3 次碰上）。

**今天的 PEAK_VMIN=2000 把垂位重试泵全部误杀**（成功案例的泵 4/5、2/3 低于该门槛）——杆第一次过冲垂死后再无泵唤醒，JUDGE 干挂到用户按停（纯自摆 0/23 的直接原因）。当时"46/64 乱泵"的统计把**垂位重试泵（功臣）**与**断路假峰泵（真害）**混为一谈；防假峰的正确手段是 trusted 判势采样（今天已独立验证有效），PEAK_VMIN 是重复防御。

**修复**：`PEAK_VMIN 2000 → 0`（恢复低速泵与重试机制；位流 **0x4200**，sha256 `da751299…`，ctrl_tb 回归 PASS、综合 0 告警）。

**验证（run10/run11，用户确认手完全离开杆）**：

| 窗口 | 结果 |
|---|---|
| run10 第 1 次启动 | **纯自摆成功**：按键→捕获 **1.54s**（首泵+1 真峰泵，-0.98°@27.9°/s 完美低速过顶）→ BAL **84.9s** 健活至用户按停 |
| run10 第 2 次启动 | 23 泵持续重试（垂位静止泵 adot 13~82 与高速泵交替，节奏与 10-24 成功案例一致），本轮未碰上低速过顶——重试机制完全复活 |

- 10-24 已实证自摆随机失败根因 = 滑环快转丢接触（adc 在真实值与浮空簇 4030~4055 间跳），旧版表现为
  46/64 泵在静止杆乱点火、5 次假捕获（0.2s 即死）、成功率 ~1/6（[SWINGUP_RANDOM_REPORT.md](../2026-10-24/SWINGUP_RANDOM_REPORT.md)）。
- 用户裁定走代码路线（硬件修复三选一延后），并要求按江协官方调参指引压平衡抖动。
- 本报告 = 一天内 4 版位流、7 个上板窗口、21 次启动的完整验证链。

## 改动清单（源码 vs 0x74A8 基线）

### A. 信号信任修复（`pendulum_ctrl.v`，治自摆成功率）

| 机制 | 参数 | 作用 |
|---|---|---|
| PEAK_VMIN 真峰门槛 | 2000 cdeg/s | judge 泵要求翻转前一刻 \|adot_prev_v\| ≥ 2000（原 1-bit 符号翻转让静止杆微摆噪声触发 46/64 乱泵） |
| trusted 判势采样 | — | judge 历史（a0/a1/adot_prev_v）只在信号干净 tick 采样，断路不写入假角度/假速度 |
| CLEAN_MS 捕获门 | 60 ms | 捕获前需连续 60ms 无 glitch（覆盖 adot 40ms 窗 + 1 个判势间隔），堵断路弹跳期的假捕获 |
| DEAD_MS 停机 | 120 ms | BAL 中连续断路 120ms → run_latch=0 干净停机（< GLITCH_HOLD_MS 200ms，抢在冻结超时前） |
| CAPT_NEAR/CAPT_LIVE 进场分类 | 1200 cdeg / 500 cdeg/s | 大偏差（>12°）进场必须是"接球式"（杆速 ≥5°/s）；静止大偏差进场被拒绝（见 run4 分析） |
| KEY_LOCK_MS 按键锁定 | 1000 ms | run_latch 翻转后 1s 内忽略按键边沿，吞掉 KEY1 接触不良的幻影第二沿 |

### B. 江协 PWM 偏移移植（`motor_driver.v` + `top.v`，治平衡低频浮动）

- 江协官方 pid-3：「横杆低频抖动 = PWM 偏移过小（0~5），摆杆高频抖动 = 偏移过大」。
- 旧实现：\|duty\| < 150 → 短刹车（stick-slip 源）。新实现：非零小命令提升到 DEADBAND 同向出力，真零命令（STOP/JUDGE/泵 wait/联锁）才刹车。
- **偏移 U 型曲线（三档实测，BAL 段零断路无混杂）**：

| DEADBAND | 稳态 alpha std（cdeg） | 颤频 | 样本 |
|---|---|---|---|
| 80 | ~220 | 0.23s | run8 自摆 BAL 101.1s |
| **150（定版）** | **~190** | **0.18s** | run3 自摆 BAL 93.8s + run9 复测 42.4s+ 两样本复现 |
| 300 | ~300 | 0.29s | 手动上摆 BAL 78.2s |

趋势与江协官方表一致（过小→慢而大、过大→快而大），**150 在 U 型底部，定版**（top.v DEADBAND=150，位流 0xF02D）。

## 结论

1. **防害目标全部达成且可复现**：旧版三重损耗（乱泵/假捕获/坏进场）+ KEY1 幻影中断在 4 版验证中零复发；三次手动助力上摆的 BAL 全部健活至用户按停/窗口尽头（93.8s / 101.1s / 42.4s+），无一次自行跌落。
2. **B（PWM 偏移）定版 150**：三档 U 型曲线（80→220 / 150→190 / 300→300+，BAL 段零断路无混杂），150 双样本复现，趋势与江协官方表一致。
3. **纯自摆 0/23 成功，死链已完整钉死**（run5 泵后逐帧证据）：真峰泵相位太准 → 2 泵即把杆推到 ~150°@300°/s 过顶速 → 转圈 1.8s 内被横杆刹车吸干能量直接垂死（无慢速过顶窗口）→ 唯一活路 = 渐进能量积累（10-24 那轮 11.9s/5 泵的路径）→ 渐进要求每摆动周期都有可信判势，而**泵后横杆快转的断路高峰恰好盖住下一峰**（转圈期间横杆被反作用拖着晃、滑环持续弹跳，run5 81.9~83.6s 每圈撞 FLOAT）→ RTL 无法凭空创造信号，代码侧无正期望改动（盲泵为负期望）。
4. **下一步二选一**：① **修滑环**（深清洁/换件/旁路飞线，判据=快晃 A 测试闪断≈0 + 连续 3 次**纯自摆**成功）——修好后渐进积累路径恢复，今天的真峰泵+接续链+进场分类直接兑现；② **演示策略改手动上摆启动**（若赛规允许）——捕获/平衡链路已 3/3 验证稳定（BAL 停止瞬间 0.65°、稳态 std ~190）。

# 2026-10-28 上板复盘：0x5E56 演示版 240 s 遥测 + 新位流 0xA0BA 验收

## 1. 本轮采集事实（cap_142832.bin）

- 板载位流 = **0x5E56**（演示版，`POS_DEMO=1`，SRAM）；SHA256 见 `cap_142832.md`。
- 11258 帧 / 11258 有效，主机平均 **46.9 Hz**，序号异常 2，跳过字节 0，最长静默 3.2 s，覆盖 236.4 s；全程 `link=1`，无 `link=0` 样本。
- 分析工具：`_tools/analyze_tlm.py`（帧级）+ `FPGA/tools_offsite/run_analysis.py`（段级，本轮新增）。

## 2. 运行结构（用户按 KEY1 自行启动/停止）

| 指标 | 值 |
|---|---|
| 运行启动次数（STOP→活跃） | 5 |
| 捕获次数（JUDGE/PUMP→BAL） | 6 |
| 其中长存活 BAL | **2 段**：35.0 s（141.4→176.4 s）、30.8 s（205.7→236.5 s，窗尽） |
| 短 BAL | 0.90 s（32.1）、0.90 s（51.0）、4.31 s（66.0）、0.11 s（99.3） |

- **纯自摆成功率 2/5 = 40%**（本窗口），与 2026-10-26 的 6/11 = 55% 同量级，无退化。
- 66.0 s 那段 BAL 内 alpha 冲到 **+60.8°** 后被出窗保护停机（FALL_WIN=70°），属正常保护，不是假捕获。
- 0.11 s 段（99.3 s）是一次未站稳的捕获，随后 STOP。

## 5. 新位流 0xA0BA：演示开关改为复位时选择

上一轮遗留：`POS_DEMO` 是编译期 localparam，抗轻推测试必须另烧一个纯平衡版（0xEA07），费时且易忘。

**为什么不是 KEY1 长按/双击**：KEY1 的按下沿已经承担 run 开/关；这颗开关在按下后约 150 ms 会掉一次接触（`KEY_LOCK_MS` 就是为它加的）。任何"靠松开沿或按住时长判定"的方案，都会让那次幻影边沿把正在运行的一轮停掉——这正是 10-25 修掉的那类事故。

**做法**：模式在复位那一刻选，此时什么都没在跑。
- 按住 **KEY1** 同时按 **KEY0**（复位）松开 → `demo_on=0`，演示关（纯平衡，抗轻推测试用）。
- 不动 KEY1 → `demo_on=1`，演示开（比赛默认）。
- 采样窗口 100 ms，按"窗口内低电平累计 ≥60 ms"判，接触抖动不会误判；之后 KEY1 仍是"按一下开/再按一下停"。
- 可观测指示：**led2 闪烁（1.5 Hz）= 演示开**；演示关时 led2 回到原来的"编码器动过亮 0.25 s"提示。
- 新增 `src/demo_sel.v` + `sim/demo_sel_tb.v`；`top.v` 用它替换 `localparam POS_DEMO`；`.gprj` 已登记新文件。

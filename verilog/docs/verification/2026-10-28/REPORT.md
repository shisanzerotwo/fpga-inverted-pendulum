# 2026-10-28 上板复盘：0x5E56 演示版 240 s 遥测 + 新位流 0xA0BA 验收

## 1. 本轮采集事实（cap_142832.bin）

- 板载位流 = **0x5E56**（演示版，`POS_DEMO=1`，SRAM）；SHA256 见 `cap_142832.md`。
- 11258 帧 / 11258 有效，主机平均 **46.9 Hz**，序号异常 2，跳过字节 0，最长静默 3.2 s，覆盖 236.4 s；全程 `link=1`，无 `link=0` 样本。
- 分析工具：`_tools/analyze_tlm.py`（帧级）+ `FPGA/tools_offsite/run_analysis.py`（段级，本轮新增）。

## 2. 运行结构（用户按 KEY1 自行启动/停止）

| 指标 | 值 |
|---|---|
| 运行启动次数（STOP→活跃） | 5 |
| 捕获次数（JUDGE/PUMP→BAL） | 6 |
| 其中长存活 BAL | **2 段**：35.0 s（141.4→176.4 s）、30.8 s（205.7→236.5 s，窗尽） |
| 短 BAL | 0.90 s（32.1）、0.90 s（51.0）、4.31 s（66.0）、0.11 s（99.3） |

- **纯自摆成功率 2/5 = 40%**（本窗口），与 2026-10-26 的 6/11 = 55% 同量级，无退化。
- 66.0 s 那段 BAL 内 alpha 冲到 **+60.8°** 后被出窗保护停机（FALL_WIN=70°），属正常保护，不是假捕获。
- 0.11 s 段（99.3 s）是一次未站稳的捕获，随后 STOP。

## 5. 新位流 0xA0BA：演示开关改为复位时选择

上一轮遗留：`POS_DEMO` 是编译期 localparam，抗轻推测试必须另烧一个纯平衡版（0xEA07），费时且易忘。

**为什么不是 KEY1 长按/双击**：KEY1 的按下沿已经承担 run 开/关；这颗开关在按下后约 150 ms 会掉一次接触（`KEY_LOCK_MS` 就是为它加的）。任何"靠松开沿或按住时长判定"的方案，都会让那次幻影边沿把正在运行的一轮停掉——这正是 10-25 修掉的那类事故。

**做法**：模式在复位那一刻选，此时什么都没在跑。
- 按住 **KEY1** 同时按 **KEY0**（复位）松开 → `demo_on=0`，演示关（纯平衡，抗轻推测试用）。
- 不动 KEY1 → `demo_on=1`，演示开（比赛默认）。
- 采样窗口 100 ms，按"窗口内低电平累计 ≥60 ms"判，接触抖动不会误判；之后 KEY1 仍是"按一下开/再按一下停"。
- 可观测指示：**led2 闪烁（1.5 Hz）= 演示开**；演示关时 led2 回到原来的"编码器动过亮 0.25 s"提示。
- 新增 `src/demo_sel.v` + `sim/demo_sel_tb.v`；`top.v` 用它替换 `localparam POS_DEMO`；`.gprj` 已登记新文件。

**验收**：

| 项 | 结果 |
|---|---|
| `iverilog -g2012 -s top src/*.v` 全工程 lint | 0 错误（声明顺序陷阱无命中） |
| `demo_sel_tb` | PASS 4/4（默认开 / 按住复位=关 / 30 ms 抖动不敏感 / 窗口后不再变化） |
| `ctrl_tb` / `loc_target_tb` / `motor_tb` / `pid_tb` / `telemetry_tb` | 全部 PASS（28 / 6 / 7 / 6 / 帧级端到端） |
| 综合告警 | 9 条，与上一版同集合，无新增 |
| 烧录 | SRAM 写入成功，UserCode `0x0000A0BA`，Status `0x00006020` |

## 6. 0xA0BA 上板试跑（cap_143604.bin）

- 烧录后用户立即起摆：**2 次启动 / 1 次捕获**，BAL 段 36.9→57.5 s（20.6 s），末尾杆摆到 **+68.7°** 触发出窗保护（FALL_WIN=70°）停机。
- **默认演示开路径上板确认**：BAL 内位置移动出现在进场后 ~5.8 s / ~9.5 s / ~13 s 的节拍上（`+204` 计数/秒的两段斜坡），与 `POS_DEMO` 时代的 13 s 循环一致 → `demo_on` 默认值 1 生效、`demo_sel` 没有把按键状态误判成"按住"。
- **停位角**：多次 move/stop 的 stop 时刻 alpha = +4.39 / -4.96 / -4.64 / -1.06 / +1.70°，仍在 ±5° 内。
- **静态抖动**：38.5–42.5 s std 2.72°、50–54 s std 2.36°（窗口内含手碰尖峰 -20.7°/+17.9°，故略高于 1.8~2.5° 的纯静置水平）。
- 期间多次 **40~60 ms 内 5~10° 的快过程**（adot 60~160 °/s），是手碰/推；单次最大把杆推到 +68.7°，保护停机而非死锁。
- **采集在 132.6 s 中断**：`SerialException: ClearCommError failed (PermissionError(13, 拒绝访问))`，随后 COM9 消失、`programmer_cli --run 0` 也读不到器件 → **主板已从 USB 断开**。SRAM 位流随断电丢失，重新连接后须重烧 0xA0BA（flash 里是旧版）。

## 7. 抗轻推测试第 2 轮（cap_160208.bin，400 s）

**结论先说：这一轮的演示没关掉，所以不是纯平衡条件下的正式抗轻推；但手推数据仍可读。**

- 18781 帧 / 400.1 s，序号异常 7，全程 link=1，无采集中断。
- **演示仍开（数据证据）**：长平衡段（251.6→296.1 s，44.6 s）里横杆每 13 s 出现一组 ±408 counts 的往返（257–259、261–263、270–271、274–275、283–284、287–288 s），与 `demo_on=1` 的 13 s 循环完全对齐；24 次 ≥8° 偏移中 **10 次正好落在这组往返上**。说明复位手势没生效（大概率是没有在"按住 KEY1"的同时去按 KEY0，或 led2 仍在闪没注意）。
- **手推事件（横杆静止同时段，12 次 ≥8° 偏移）**：峰值 9.0~17.0°，**全部自行回正**，恢复 0.08~0.63 s；最后一次（295.4 s）之后整段平衡结束 = 用户按 KEY1 停机，不是跌落。
- **演示移动本身**也把杆掀到 16~19°，恢复要 1.3~2.7 s（横杆一边走一边要收敛），比手推慢一个量级——这正是必须把演示关掉才能测抗推的原因。
- **启动/捕获统计（本轮 13 次启动）**：7 次捕获，但只有 2 段成规模（4.35 s、228.7 s；44.56 s、251.6 s）；另 5 次"捕获"在 0.04~0.63 s 内就死掉，入场角在 **-34~-48°**。若这几段是手扶后松手，属于"放得太歪"（捕获门允许 |α|>12° 时以 ≥5°/s 运动入场，随后立刻出窗），不是门限回归；手扶进场请放到 **±10° 内**再松手。
- **静态抖动**（横杆静止窗口）：264.3–269 s std 2.12°、276–279 s std 2.31°、289–294 s std 1.72°，与机械地板一致。

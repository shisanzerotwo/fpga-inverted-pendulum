# 规划修订 v2：只用立创·逻辑派 FPGA-G1 完成开发

> **约束（用户 2026-10-01 明确）**：不购买任何额外芯片/模块，**只用这块开发板** + 江协套件本体（电机/编码器/摆角电位器/驱动板）。
> 本文只写**已核实的事实**（附来源），未核实的显式标 `[待核实]`。
> 距截止 11-10 剩 40 天（稳摆硬线 10-20、起摆硬线 10-27）。

---

## 一、这个约束把方案锁死了

原规划摆角采集主路径是"外置 SPI ADC（MCP3202）"——**需外购芯片，与"只用这块板"冲突，排除**。
剩下唯一可行路径：**用板上 GD32F303 自带的 ADC 采样，再把原始码值转发给 FPGA。**

关键是这条路**能不能只用板载资源走通** → 见 §二 的核实结果（结论：**能，且不需要飞线**）。

---

## 二、硬件核实（决定性证据）

### 2.1 FPGA 侧没有 ADC（已核实）

- 高云 ADC 用户手册 **UG299E** 的支持器件表只有 **Arora 系列**（GW5A/5AR/5AS/5AT、GW3A）
- GW2A 数据手册（DS102）功能列表无 ADC
- `GW2A-LV18PG256C8/I7` **不在支持列表内**

### 2.2 排针上的 ARM 引脚 = 6 个，**其中 PB0 带 ADC 通道**（本次关键发现）

**来源 1 — 原理图 `2.esch` 网络名**（带 `EX_` 前缀者 = 引到排针）：

```
EX_PA11   EX_PA12   EX_PB0   EX_PB9   EX_PB10   EX_PB11      ← 正好 6 个，与 wiki "ARM 占 6 个 I/O" 一致
PA0 … PA7                                                     ← 不带 EX_ 前缀 = 板内直连，不引排针
```

**来源 2 — GD32F303xx 数据手册 Rev1.9 引脚定义**：

```
PB0  引脚 46   Alternate: ADC01_IN8, TIMER2_CH2 …
PB1  引脚 47   Alternate: ADC01_IN9, TIMER2_CH3 …
```

→ **排针上的 `EX_PB0` = GD32 的 ADC01_IN8**，12bit SAR，转换速率 1MHz 级。

**来源 3 — 官方引脚分配表（ARM 段）**：PB0 **未被任何板载功能占用**（PB1 被 LCD 背光占用，PB0 空闲）→ 引到排针供用户使用，符合设计意图。

> ⚠️ 仅 **1 路**模拟输入可用（6 个排针脚里只有 PB0 有 ADC 功能）。本项目**只需摆角 1 路**，正好够用；若日后要第二路模拟量（如电池电压），则无解。

### 2.3 `PA0~PA7` = FPGA ↔ GD32 直连通道（官方引脚表原文）

| GD32 脚 | FPGA 球号 | 官方标注功能 |
|---|---|---|
| PA0 | `J12` | USART1_CTS |
| PA1 | `J11` | USART1_RTS |
| PA2 | `K11` | USART1_TX |
| PA3 | `D14` | USART1_RX |
| PA4 | `E15` | SPI0_NSS |
| PA5 | `L12` | SPI0_SCK |
| PA6 | `L13` | SPI0_MISO |
| PA7 | `L16` | SPI0_MOSI |

→ 这 8 个是**板内走线**（不在排针上），项目原标注为"合规红线，默认不使用"。改用方案 B 后**必须启用**，写进 `.cst`。

**官方 wiki 独立印证**（`https://wiki.lckfb.com/zh-hans/fpga-ljpi/communication/io.html` 「I/O 交互」页）：

| 信号 | 方向 | 引脚 | 端口作用 |
|---|---|---|---|
| PA0 | input | `J12` | A |
| PA1 | input | `J11` | B |
| **PA2** | input | **`K11`** | **C** |

→ 因此 `K11 = PA2` 具备**三源**：官方引脚分配表 + 官方 wiki 表 + 原理图 `2.esch`；方向也一致（ARM 输出 → FPGA 输入），`adc_bridge` 的 `rx` 接 `K11` 成立。该页还含官方 GD32 侧初始化代码，可作固件风格参考。

### 2.4 调试/串口通道（已实测）

| 通道 | 接口 | Windows 侧 | 功能 |
|---|---|---|---|
| FPGA | 下载器 **8P** | **`COM9`**（`FTDIBUS\VID_0403&PID_6010`） | 下载 + GAO 仿真 + **虚拟串口** |
| ARM | 下载器 **6P** | **`COM7`**（`USB\VID_0D28&PID_0204&MI_01`） | DAP 下载 + Debug + **虚拟串口** |
| **约束** | **FPGA 与 ARM 不能同时使用，需按键切换**（wiki 原文） | | |

实测印证：17:12:47 DAPLink 身份移除 → 17:12:48 FTDI 身份到达（**间隔 1 秒**），`LocationInfo` 同为 `Port_#0004.Hub_#0001`。

### 2.5 接线红线（wiki 原文）

> 下载器 / USB / HDMI / 排针**共用同一 5V 网络**；**排针处仅允许输出 +5V，绝对禁止从外部向排针输入 +5V**，否则可能损坏器件。

→ 电位器供电只能取排针的 `3V3`（单向），严禁外接 5V 倒灌。

### 2.6 其他已核实项

- `L15` 双重身份：官方表 `usb_dp_pull`，同时又出现在 `EX_` 清单（`EX_IOT2A_L15`）→ **本项目不使用 L15**
- 板载 USB 口接 FPGA 的 `M14/M15` → 该两脚不可作他用
- 板载**1 位数码管（8 段 = A~G+DP，共阳、低电平点亮）**（`G13/H16/H12/H13/H14/G12/G11/L14`）**本来就有** → `seg_display` 恢复为**正式项**（**无位选、不需动态扇描**，比原规划写的“8 位扇描”简单得多；官方 wiki 给了段码表 0=0xC0…9=0x90）

## 三、定案方案：GD32 ADC 桥（"方案 B"）

```
江协摆角电位器 SV01A103AEA01R00（10K，有效 333°，0~3.3V）
        │  接排针：EX_PB0 + GND + 3V3（单向）
        ▼
GD32F303  ADC01_IN8（12bit SAR）  ── 只做：采样 + 原始码值直传
        │  板内直连通道 PA0~PA7（USART1 或 SPI0）
        ▼
FPGA（GW2A-18）── 滤波 / 角度换算 / 双环 PID / 能量起摆 / PWM 全部在此
        │
        ▼
TB6612（G15/G14/G16）→ 编码电机 ；编码器（J15/K16）→ FPGA
```

**每侧职责（务必按此写代码与写报告）**

| 侧 | 只做这些 | 明令不做 |
|---|---|---|
| GD32 | ADC 采样 PB0、把 12bit 原始码值发给 FPGA | **不做滤波、不做换算、不做任何判断、不碰电机** |
| FPGA | 同步/滤波、角度换算、控制律、PWM、状态机 | — |

## 四、合规论证（本方案最大的软肋，必须留证据）

**规则要求**（项目 AGENTS.md 记载）：感知→滤波→控制律→PWM **全链路用 RTL 实现于 FPGA 内部**，MCU **不得承载控制算法**，最终作品保持空闲。

**本方案的差距**：感知链路的**物理层**（ADC 采样）落在 MCU 上。

**项目已有的口径记录**（`备赛总结与规划.md` §1.5-4，2026-09-29）：
> "MCU 侧**允许做纯数据采集转发**（ADC 采样 → 原始码值直传 FPGA，无滤波/无运算/无控制决策），不违规。"

⚠️ **这条口径的来源未在文档中注明**（是组委答复？还是项目自身解读？）→ 标 `[待核实]`。

**应对**：
1. **优先向组委书面确认**（一句话问清："外部 ADC 采样由板载 MCU 完成、仅原码转发，是否满足全链路 FPGA 要求"）
2. 若无法确认，**报告里主动声明**：GD32 代码仅 ADC 采样 + 转发（可附源码与二进制），全部算法在 FPGA 内，作品主要功能不依赖 MCU 计算
3. 保留 GD32 固件源码作为"无算法"的佐证

**风险等级：中高**（若组委严格解释"感知"，则需另想纯 FPGA 思路，见 §八 备选）
